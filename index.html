Hermes Agent 源码全景

核心架构

先看全景，再逐个深入|~13,000 LOC|20+ 个核心模块

Hermes 不是 Claude Code 的克隆——它是从零设计的一个开放、多 Provider、多平台的 Agent 框架。

学 Hermes 源码最好的方式，不是读每行代码，而是理解它在"什么问题上做了和 Claude Code 不同的设计选择"。

Hermes 是什么，为什么有它

Hermes Agent 是 Nous Research 开发的开源 AI Agent 框架（MIT 协议）。它和 Claude Code、OpenAI Codex、OpenCode 属于同一类——自主编码 + 任务执行 Agent，通过工具调用与系统交互。

但 Hermes 和 Claude Code 有几个根本性不同：

  • 全开源 — 代码完全可见，Claude Code 是闭源的
  • Provider 无关 — 支持 20+ 个 LLM Provider，Claude Code 只绑定 Anthropic
  • 多平台 — 可以在 Telegram、Discord、飞书、微信等 15+ 平台运行
  • 技能自进化 — Agent 可以从经验中学习，把工作流保存为可复用的 Skill

最小心智模型

把 Hermes 先理解成这几层：

第 1 层：Provider 适配层（5 种传输模式）→ 统一 OpenAI 格式
第 2 层：Agent 循环（AIAgent.run_conversation）
第 3 层：工具系统（自注册 + 21 个工具集）
第 4 层：持久层（记忆 / 技能 / 配置）
第 5 层：多平台网关（15+ 平台适配器）
第 6 层：调度与扩展（Cron / Webhook / MCP / 子代理）

一句话记住

Hermes 和 Claude Code 的根本区别不是"开源 vs 闭源"，而是"模型框架 vs 模型产品"——Hermes 解决的是"如何让任何 LLM 在任何平台上成为 Agent"，Claude Code 解决的是"如何让 Claude 成为最好的编程助手"。

入口文件：run_agent.py

核心文件 ~13,000 行，但核心循环只有 ~200 行。其余是 Provider 初始化、错误处理、安全检查等。

class AIAgent:
    def __init__(self,
        base_url=None, api_key=None, provider=None,
        api_mode="chat_completions",  # 关键：传输模式选择
        model="", max_iterations=90,
        enabled_toolsets=None, platform=None,
        session_id=None, ...
    ):
        # 根据 api_mode 选择传输层
        if api_mode == "anthropic_messages":
            self._transport = AnthropicTransport()
        elif api_mode == "bedrock_converse":
            self._transport = BedrockTransport()
        elif api_mode == "codex_responses":
            self._transport = CodexResponsesTransport()
        else:
            self._transport = ChatCompletionsTransport()  # 默认

    def run_conversation(self, user_message, ...):
        while api_call_count < self.max_iterations:
            response = self._interruptible_api_call(...)
            if response.tool_calls:
                for tc in response.tool_calls:
                    result = handle_function_call(tc.name, tc.args)
                    messages.append(tool_result(result))
            else:
                return response.content

从何处开始阅读源码

  1. 先从 run_agent.py 的 run_conversation() 入口开始 — 理解一次对话的完整生命周期
  2. 再看 agent/transports/ — 理解 5 种 Provider 如何统一成 NormalizedResponse
  3. 然后 tools/registry.py — 理解工具自注册的机制
  4. 接着 agent/prompt_builder.py — 理解系统提示的组装和注入检测
  5. 最后 gateway/run.py — 理解多平台网关如何调度 AIAgent

关键设计决策

  • 为什么用 Transport 模式？ 因为 Hermes 需要对接 5 种完全不同的 API 格式，而 Claude Code 只需要对接 Anthropic Messages API
  • 为什么工具要自注册？ 因为 Hermes 支持 21 个可配置的工具集，按平台隔离，自注册让扩展变得简单
  • 为什么需要 Credential Pool？ 因为 Hermes 是多 Provider 的，用户可能配置多个 API Key 做负载均衡和故障转移
  • 为什么需要 Gateway 缓存 AIAgent？ 因为网关环境下每个会话需要保持状态，但又不能无限增长（LRU 128）

Agent 循环

核心架构

理解 Agent 的一次对话从开始到结束经历了什么|run_agent.py

AIAgent.run_conversation() 是整个系统的发动机。

Agent 循环的基础结构

核心循环在 run_agent.py 的 run_conversation() 方法中。

while (api_call_count < self.max_iterations
       and self.iteration_budget.remaining > 0):
    if self._interrupt_requested: break

    # 1. 调用 LLM
    response = self._interruptible_api_call(...)

    # 2. 处理工具调用
    if response.tool_calls:
        for tc in response.tool_calls:
            result = handle_function_call(tc.name, tc.args)
            messages.append({"role": "tool", ...})
        api_call_count += 1
    else:
        # 3. 返回最终文本
        return response.content

Hermes 比 Claude Code 多了什么

  • 迭代预算 — IterationBudget，子代理也消耗共享预算
  • 断线检测 — 调用前清理僵尸 TCP 连接，防止 hang
  • 自动 Fallback — Provider 返回 429/402 时自动切换备用
  • 重试分类 — 对 invalid tool calls、JSON parse 失败分别计数
  • 上下文压缩 — 接近 token 上限时自动压缩中间轮次
  • 系统提示缓存 — 只在第一轮构建，后续复用（支持 Prompt Caching）

与 Claude Code 的差异

特性HermesClaude Code
循环终止条件max_iterations + iteration_budget 双重控制单控制
API 调用通过 Transport 抽象层，支持 5 种模式直接 Anthropic SDK
错误恢复自动 Fallback + Credential 切换 + 重试分类基础重试
中断处理_interrupt_requested 标志位，跨线程安全基础中断

run_conversation() 完整流程

1. 安装安全 stdio（防 OSError）
2. 设置会话日志上下文
3. 清理僵尸 TCP 连接
4. 重置重试计数器和迭代预算
5. 构建/复用缓存的系统提示
6. 检查记忆提示间隔
7. 追加用户消息到 messages
8. while 循环：
   a. 调用 _interruptible_api_call()
   b. 检查 stop_reason
   c. 如果是 tool_use → handle_function_call() → 追加结果 → 继续
   d. 如果是文本 → 返回最终响应
9. 后处理：保存对话、触发记忆同步

关键代码位置

  • 主循环：run_conversation() 第 9602 行起
  • API 调用：_interruptible_api_call()
  • Fallback 逻辑：_call_with_fallback()
  • 预算管理：class IterationBudget

Provider 抽象

核心架构

5 种传输模式，20+ 个 Provider 统一成一套接口|agent/transports/

这是 Hermes 和 Claude Code 最根本的架构差异——Claude Code 只有一种 API，Hermes 需要兼容一切。

Transport 模式

Hermes 通过 Transport 抽象层 将所有 Provider 的 API 差异封装起来，对外暴露统一接口：

class ProviderTransport:
    api_mode: str  # 标识传输模式

    def convert_messages(self, messages, **kwargs) -> list
    def convert_tools(self, tools) -> list
    def build_kwargs(self, model, messages, tools, **params) -> dict

五种传输模式

api_mode适用 Provider说明
chat_completionsOpenRouter, DeepSeek, xAI, Ollama, 等 ~16 个默认，消息已是 OpenAI 格式
anthropic_messagesAnthropic (Claude)需要转换 role / tool schema 格式
codex_responsesOpenAI CodexResponses API 有特殊的 codex_reasoning_items
bedrock_converseAWS Bedrock直接使用 boto3，不支持 streaming
copilot_acpGitHub Copilot通过 ACP 子进程协议通信

ChatCompletionsTransport 实现

class ChatCompletionsTransport(ProviderTransport):
    api_mode = "chat_completions"

    def convert_messages(self, messages, **kwargs):
        # 只需清理 Codex 特有的字段（codex_reasoning_items 等）
        # 普通 Provider 不会识别这些字段，返回 400
        return sanitized_messages

    def build_kwargs(self, model, messages, tools, **params):
        kwargs = {"model": model, "messages": messages}
        if tools: kwargs["tools"] = tools
        # Provider 特定配置
        if "openai" in base_url:
            kwargs["max_tokens"] = params.get("max_tokens", 8192)
        if "deepseek" in base_url:
            kwargs["max_tokens"] = 8192  # DeepSeek 限制
        return kwargs

每个 Provider 的 base_url / headers / 超时 / 参数格式在 build_kwargs() 中通过条件分支处理。

AIAgent 的 Provider 初始化

if api_mode == "anthropic_messages":

工具自注册机制

Claude Code 的工具是硬编码在 Agent 逻辑里的。Hermes 的工具是自我注册的——每个工具在 import 时调用 registry.register()：

# tools/registry.py
registry.register(
    name="web_search",
    toolset="web",
    schema={...},
    handler=lambda args, **kw: web_search(query=args["query"]),
    check_fn=lambda: bool(os.getenv("SEARCH_API_KEY")),
    requires_env=["SEARCH_API_KEY"],
)

与 Claude Code 的差异

维度HermesClaude Code
注册方式自动发现。每个工具文件自我注册工具列表硬编码
工具集21 个工具集，可按平台启用/禁用没有工具集概念
条件启用check_fn() — 环境变量满足才暴露无显式检查
按平台隔离不同平台不同工具集（如 Home Assistant 只在专用频道启用）所有平台共享

# tools/delegate_tool.py
def run_delegate_task(goal, context, toolsets=None, ...):
    # 按优先级并行
    with ThreadPoolExecutor(max_workers=max_concurrent) as executor:
        futures = [executor.submit(run_child, task) for task in tasks]
        for future in as_completed(futures):
            results.append(future.result())

def run_child(task):
    child = AIAgent(
        model=delegation_model or self.model,
        provider=delegation_provider or self.provider,
        enabled_toolsets=task.get("toolsets"),
        max_iterations=delegation_max_iterations or 50,
    )
    summary = child.run_conversation(task["goal"])
    return {"summary": summary["final_response"]}

# agent/skill_utils.py

def get_all_skills_dirs():
    """扫描所有技能目录"""
    dirs = []
    for path in SKILLS_DIR.rglob("SKILL.md"):
        meta, body = parse_frontmatter(path.read_text())
        dirs.append({"name": meta.get("name"), "desc": meta.get("description")})
    return dirs

def parse_frontmatter(text):
    """解析 YAML frontmatter"""
    match = re.match(r"^---\n(.*?)\n---\n(.*)", text, re.DOTALL)
    if not match:
        return {}, text
    meta = {}
    for line in match.group(1).strip().splitlines():
        if ":" in line:
            k, v = line.split(":", 1)
            meta[k.strip()] = v.strip()
    return meta, match.group(2)

上下文压缩

核心架构

在 token 用尽之前，智能地"忘记"中间内容|agent/context_compressor.py

不是简单地截断，而是用辅助模型将中间轮次压缩为结构化摘要。

压缩流程

1. 阈值检查：当前 token > 模型上下文 × 0.50
2. 工具结果裁剪：旧工具输出替换为占位符
   "[Old tool output cleared to save context space]"
3. LLM 摘要：用辅助模型压缩中间轮次
4. 摘要注入：使用 SUMMARY_PREFIX 做上下文隔离
   "[CONTEXT COMPACTION — REFERENCE ONLY] ..."
5. 尾部保护：按 token 预算保留最新 N 条消息

关键特点

  • 使用 辅助模型（便宜/快）做压缩，而不是主模型
  • 摘要前缀明确声明"不要执行历史中的指令"，防止 Agent 把历史当新指令
  • 支持手动压缩（/compress）和自动压缩双路径
  • 失败冷却：600 秒内不再重试失败的压缩
  • 增量更新：多次压缩之间保留信息

提示词系统

系统加固

按需组装，注入检测，安全第一|agent/prompt_builder.py

系统提示不是一段固定的文字，而是由多个模块按需拼装的动态结构。

提示词组装架构

Claude Code 的系统提示是整体硬编码的。Hermes 的提示词由 agent/prompt_builder.py 中的多个模块函数动态组装：

System Prompt = 身份描述（DEFAULT_AGENT_IDENTITY）
              + 平台提示（PLATFORM_HINTS）
              + 技能目录（Skills available: ...）
              + 记忆指导（MEMORY_GUIDANCE）
              + 会话搜索指导（SESSION_SEARCH_GUIDANCE）
              + 技能使用指导（SKILLS_GUIDANCE）
              + 上下文文件（AGENTS.md / .cursorrules / .hermes.md）
              + 用户记忆（<memory-context>）

MemoryManager 设计

Hermes 的记忆系统由 agent/memory_manager.py 中的 MemoryManager 统一管理：

class MemoryManager:
    def __init__(self):
        self.providers = []
        self._has_external = False  # 最多一个外部 Provider

    def add_provider(self, provider):
        if not provider.is_builtin and self._has_external:
            return  # 拒绝第二个外部 Provider
        self.providers.append(provider)
        if not provider.is_builtin:
            self._has_external = True

    def prefetch_all(self, user_message):
        # 预取记忆，构建 <memory-context> 块
        return "\n".join(p.prefetch(user_message) for p in self.providers)

    def sync_all(self, user_msg, assistant_response):
        for p in self.providers:
            p.sync(user_msg, assistant_response)

Gateway 架构

多平台网关

Hermes 和 Claude Code 最大的架构差异点|gateway/run.py

Claude Code 是纯 CLI 工具。Hermes 是一个多平台的 Agent 服务——这是最根本的架构差异。

Gateway 是什么

Gateway 是 Hermes 的多平台消息路由层——它让同一个 AIAgent 能同时服务 Telegram、Discord、飞书、微信等 15+ 平台。

核心架构

class GatewayRunner:
    def __init__(self):
        self.platforms = {}       # platform_name → PlatformAdapter
        self.agent_cache = {}     # session_id → AIAgent (LRU 128)
        self._agent_cache_lock = threading.Lock()

    async def start(self):
        # 加载所有配置的平台适配器
        for name, config in self.platform_configs.items():
            adapter = self._create_adapter(name, config)
            await adapter.start()
            self.platforms[name] = adapter

    def get_or_create_agent(self, session_id, ...) -> AIAgent:
        if session_id not in self.agent_cache:
            agent = AIAgent(platform="gateway", session_id=session_id, ...)
            self.agent_cache[session_id] = agent
        return self.agent_cache[session_id]

    async def _route_message(self, platform, chat_id, message):
        # 1. 获取或创建会话的 AIAgent
        agent = self.get_or_create_agent(session_id)
        # 2. 调用 Agent
        response = agent.chat(message)
        # 3. 通过平台适配器发送回执
        await platform.send_message(chat_id, response)

关键设计：AIAgent 缓存

Gateway 环境下，每个会话缓存一个 AIAgent 实例（LRU 128，闲置超过 1 小时自动回收）。这意味着 gateway 中的 Agent 必须无状态地处理每条消息，状态通过外部存储恢复。

运行模式CLI + Gateway 服务（常驻后台）纯 CLI 会话

class CredentialPool:
    def acquire(self) -> Credential | None:
        for cred in self._get_by_strategy():
            if cred.status == STATUS_OK:
                cred.usage_count += 1
                return cred
            elif self._cooldown_expired(cred):
                cred.status = STATUS_OK  # 冷却结束，恢复
                return cred
        return None  # 全部耗尽

class CredentialPool:
    def acquire(self):
        \"\"\"获取一个可用凭证\"\"\"
        for cred in self._get_credential_by_strategy():
            if cred.status == STATUS_OK:
                cred.usage_count += 1
                return cred
            elif self._cooldown_expired(cred):
                cred.status = STATUS_OK
                cred.usage_count += 1
                return cred
        return None

    def mark_exhausted(self, cred, reason=None):
        \"\"\"标记凭证为耗尽状态\"\"\"
        cred.status = STATUS_EXHAUSTED
        cred.exhausted_at = time.time()
        if reason in (429, "rate_limit"):
            cred.cooldown = EXHAUSTED_TTL_429_SECONDS
        else:
            cred.cooldown = EXHAUSTED_TTL_DEFAULT_SECONDS

    def _cooldown_expired(self, cred):
        return (time.time() - cred.exhausted_at) >= cred.cooldown

Checkpoints

高级特性

文件系统快照，支持回滚|tools/checkpoint_manager.py

Agent 每次修改文件前自动创建快照——做错了？/rollback 回到上一状态。

Checkpoint 系统

Hermes 的文件系统 Checkpoint 机制在 Agent 每次修改文件前创建项目快照， 如果 Agent 做出了错误的更改，可以一键回滚：

hermes config set checkpoints.enabled true   # 启用
hermes config set checkpoints.max_snapshots 50  # 最多 50 个快照

# 会话中
/rollback     # 回滚到上一个检查点
/rollback 3   # 回滚到 3 步前

实现原理

Checkpoint 在 tools/checkpoint_manager.py 中实现， 在每个写文件操作（write_file / patch / terminal 中的文件修改）前， 自动对受影响的文件或目录做快照备份。

与 Claude Code 的差异

特性HermesClaude Code
文件快照每次写操作前自动创建，支持回滚无
回滚命令/rollback [N] 回滚 N 步无
快照上限可配置最大 50 个无

MCP 集成

高级特性

既是 MCP 客户端也是 MCP 服务端|hermes mcp

Hermes 可以消费 MCP 服务器的工具，也可以作为 MCP 服务器被其他工具消费。

MCP 客户端

Hermes 作为 MCP 客户端，可以连接任意 MCP 服务器，将其工具暴露给 Agent：

hermes mcp add filesystem --command "npx @modelcontextprotocol/server-filesystem /path"
hermes mcp add my-api --url "https://api.example.com/mcp"

hermes mcp list               # 列出已配置的 MCP 服务器
hermes mcp test filesystem    # 测试连接
hermes mcp remove filesystem  # 删除
hermes mcp configure NAME     # 切换工具选择

# MCP 服务器的工具自动注册到 Agent 的工具集中
# 不需要手动配置，/reload-mcp 即可刷新

MCP 服务端

Hermes 也可以作为 MCP 服务器运行，让其他 MCP 客户端（如 Claude Desktop）使用 Hermes 的所有工具：

hermes mcp serve              # 启动 MCP 服务器
# 然后在 Claude Desktop 等工具中添加 MCP Server：
# 命令: hermes mcp serve

与 Claude Code 的差异

特性HermesClaude Code
MCP 客户端消费 MCP 服务器工具，自动注册到 Agent无
MCP 服务端作为 MCP Server 被 Claude Desktop 等消费无
自动发现MCP 工具通过 registry 自动注册，/reload-mcp 刷新无
