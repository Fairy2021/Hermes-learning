Hermes Agent 源码全景

核心架构

先看全景，再逐个深入 | ~13,000 LOC| 20+ 个核心模块

Hermes 不是 Claude Code 的克隆——它是从零设计的一个开放、多 Provider、多平台的 Agent 框架。

学 Hermes 源码最好的方式，不是读每行代码，而是理解它在"什么问题上做了和 Claude Code 不同的设计选择"。

Hermes 是什么，为什么有它

Hermes Agent 是 Nous Research 开发的开源 AI Agent 框架（MIT 协议）。 它和 Claude Code、OpenAI Codex、OpenCode 属于同一类——自主编码 + 任务执行 Agent， 通过工具调用与系统交互。

但 Hermes 和 Claude Code 有几个根本性不同：

  • 全开源 — 代码完全可见，Claude Code 是闭源的
  • Provider 无关 — 支持 20+ 个 LLM Provider，Claude Code 只绑定 Anthropic
  • 多平台 — 可以在 Telegram、Discord、飞书、微信等 15+ 平台运行
  • 技能自进化 — Agent 可以从经验中学习，把工作流保存为可复用的 Skill

💡 本文的核心视角

对照 Claude Code 的设计哲学来理解 Hermes。两者的"为什么"比"怎么做"更有学习价值。

最小心智模型

把 Hermes 先理解成这几层：

第 1 层：Provider 适配层（Chat Completions / Anthropic / Codex / Bedrock / Copilot ACP）
  → 统一成 OpenAI 格式的消息 + 工具

第 2 层：Agent 循环（run_agent.py / AIAgent）
  → 循环：调用 LLM → 解析工具调用 → 分发 → 追加结果 → 继续

第 3 层：工具系统（tools/ + model_tools.py）
  → 每个工具自我注册，按工具集分组，条件启用

第 4 层：持久层（记忆 / 技能 / 配置）
  → 跨会话记忆、按需技能加载、配置文件

第 5 层：多平台网关（gateway/）
  → 统一消息路由，平台适配器模式

第 6 层：调度与扩展（Cron / Webhook / MCP / 子代理）
  → 定时任务、事件触发、IDE 集成、并行工作流

与 Claude Code 的核心差异

最核心的一句话：Claude Code 是一个"Claude 专属"的工具，Hermes 是一个"任何模型都可以用的 Agent 框架"。

这个设计前提的差异，往下渗透到了每一层架构。

1. Provider 抽象 —— 核心差异

Claude Code 只面向 Anthropic API（Messages API），Hermes 需要支持任意 OpenAI 兼容 Provider。

维度HermesClaude Code
适配模式 Transport 模式。每个 api_mode 一个 Transport 类， 统一输出 NormalizedResponse（tool_calls + content + usage） 直接使用 Anthropic Python SDK
覆盖范围 chat_completions（OpenAI 兼容）/ anthropic_messages / codex_responses / bedrock_converse / copilot_acp — 共 5 种传输模式 仅 Anthropic Messages API
Provider 特定逻辑 每个 Provider 有自己的 base_url / headers / 超时 / 参数格式， 在 build_kwargs() 中通过条件分支处理 所有请求走同一套 SDK，无 Provider 差异

来看关键代码。在 run_agent.py 中，AIAgent 的 __init__ 根据 api_mode 选择不同的初始化路径：

# run_agent.py — AIAgent.__init__ (简化)
if self.api_mode == "anthropic_messages":
    self.client = Anthropic(api_key=api_key, base_url=base_url)
    self._transport = AnthropicTransport()
elif self.api_mode == "bedrock_converse":
    self._bedrock_region = re.search(r"bedrock-runtime\.([a-z0-9-]+)", base_url).group(1)
    self.client = None  # 直接使用 boto3
elif self.api_mode == "codex_responses":
    self.client = OpenAI(api_key=api_key, base_url="https://api.openai.com")
    self._transport = CodexResponsesTransport()
else:
    # chat_completions — 默认路径，覆盖 ~16 个 Provider
    self.client = OpenAI(api_key=api_key, base_url=base_url)
    self._transport = ChatCompletionsTransport()

2. 核心 Agent 循环

在 run_agent.py 的 run_conversation() 方法中（~3600 行）， Hermes 的 Agent 循环和 Claude Code 的结构类似，但多了很多层：

# run_agent.py — run_conversation() 核心循环逻辑
while (api_call_count < self.max_iterations
       and self.iteration_budget.remaining > 0) \
        or self._budget_grace_call:

    if self._interrupt_requested:
        break

    # 1. 调用 LLM（通过 transport 层）
    response = self._interruptible_api_call(
        model=self.model,
        messages=messages,
        tools=tool_schemas,
    )

    # 2. 处理工具调用
    if response.tool_calls:
        for tool_call in response.tool_calls:
            result = handle_function_call(
                tool_call.name, tool_call.args, task_id
            )
            messages.append(tool_result_message(result))
        api_call_count += 1
    else:
        # 3. 返回最终文本
        return response.content

Hermes 比 Claude Code 多了什么：

  • 迭代预算 — IterationBudget，子代理消耗共享预算
  • 断线检测 — _cleanup_dead_connections()，在 API 调用前清理僵尸 TCP 连接
  • 自动 Fallback — 当主 Provider 返回 429/402 时，自动切换到备用 Credential
  • 重试分类 — 针对 invalid tool calls、JSON parse 失败、空内容等分别计数和重试
  • 上下文压缩 — 当接近 token 限制时，自动压缩中间轮次
  • 记忆提示 — 每隔 N 轮自动提醒 Agent 查阅记忆
  • 系统提示缓存 — 只在第一轮构建，后续复用（支持 Anthropic Prompt Caching）

3. 工具系统 —— 自注册 + 按工具集分组

这是 Hermes 和 Claude Code 差异很大的区域。Claude Code 的工具是硬编码在 Agent 逻辑里的， Hermes 的工具是自我注册的。

# tools/registry.py — 每个工具在 import 时自我注册
registry.register(
    name="web_search",
    toolset="web",
    schema={
        "name": "web_search",
        "description": "Search the web",
        "parameters": {
            "type": "object",
            "properties": {"query": {"type": "string"}},
            "required": ["query"],
        },
    },
    handler=lambda args, **kw: web_search(query=args["query"]),
    check_fn=lambda: bool(os.getenv("SEARCH_API_KEY")),
    requires_env=["SEARCH_API_KEY"],
)
维度HermesClaude Code
注册方式 自动发现。tools/*.py 中只要有 registry.register() 调用， 在 import 时自动注册。不需要手动维护列表 工具列表硬编码在 Agent 的 tool 定义中
工具集 21 个工具集（web/browser/terminal/vision/delegation 等）， 可针对每个平台启用/禁用 没有工具集概念，所有工具有了就有
条件启用 check_fn() — 只有环境变量满足时才暴露给模型 工具按需出现，无显式检查
按平台隔离 不同的消息平台可以有不同工具集（如 Home Assistant 只在专用频道启用） 所有平台共享同一套工具

工具集的定义在 toolsets.py 里：

4. 子代理系统 —— 并行 + 隔离

和 Claude Code 一样，Hermes 也支持子代理（delegate_task）。但 Hermes 的版本更灵活：

# 子代理的受限工具集
DELEGATE_BLOCKED_TOOLS = frozenset([

    "memory",         # 禁止写入共享记忆
    "send_message",   # 禁止跨平台副作用
    "execute_code",   # 子代理应该一步步推理
])

# 每个子代理在独立线程中运行：
with ThreadPoolExecutor(max_workers=max_concurrent) as executor:
    futures = [executor.submit(run_child, task) for task in tasks]
    for future in as_completed(futures):
        results.append(future.result())
特性HermesClaude Code
并行度 支持批量并行子代理（默认最多 3 个），各自独立 terminal 串行子代理
隔离级别 每个子代理有独立的 task_id、terminal 会话、文件状态缓存 共享终端状态

ACP 子进程 可以委托给外部 ACP 进程（如 Claude Code CLI、Codex CLI） 仅内部子进程

5. 技能系统 —— 自进化的知识库

这是 Hermes 最有特色的系统。Claude Code 的 CLAUDE.md / .cursorrules 是静态配置， 而 Hermes 的 Skills 是动态的、可积累的、Agent 自己维护的知识库。

# agent/skill_utils.py — 技能文件系统结构
# 每个技能是一个目录，里面至少有一个 SKILL.md
skills/
  code-review/
    SKILL.md          # YAML frontmatter + Markdown 正文
  git-workflow/
    SKILL.md
    templates/        # 可选模板文件
    references/       # 可选参考文档
    scripts/          # 可选脚本

# skill_view() 读取时解析 frontmatter，提取 name/description/tags
# 然后作为工具结果注入当前上下文

关键区别：

  • Claude Code 的 CLAUDE.md 是 项目级静态配置——需要手动编辑，永远不会自动更新
  • Hermes 的 Skill 是 Agent 自维护的——Agent 可以用 skill_manage() 工具创建、更新、删除技能
  • 按需加载 — 技能目录在 system prompt 里只有名字+描述，正文在需要时才通过 skill_view() 加载
  • 共享生态 — 支持技能市场（hermes skills browse）、GitHub 源（hermes skills tap add REPO）

6. 记忆系统 —— 多 Provider 可插拔

# agent/memory_manager.py — 核心设计
class MemoryManager:
    """管理内置记忆 Provider + 最多一个外部插件 Provider"""

    def __init__(self):
        self.providers = []
        self._has_external = False  # 最多允许一个外部 Provider

    def add_provider(self, provider: MemoryProvider):
        if not provider.is_builtin and self._has_external:
            logger.warning("Only one external memory provider allowed. Rejecting %s", provider.name)
            return
        self.providers.append(provider)
        if not provider.is_builtin:
            self._has_external = True

    def prefetch_all(self, user_message: str) -> str:
        """预取所有记忆，构建  块"""
        parts = []
        for p in self.providers:
            parts.append(p.prefetch(user_message))
        return "\n".join(parts)

    def sync_all(self, user_msg: str, assistant_response: str):
        """同步记忆到所有 Provider"""
        for p in self.providers:
            p.sync(user_msg, assistant_response)

Claude Code 的记忆系统是 Anthropic 内置的（项目知识 + 用户偏好记忆），不可扩展。

Hermes 的记忆系统可插拔：内置 Provider、Honcho、Mem0、Supermemory 等。Agent 每 N 轮自动回顾记忆。

7. 多平台网关 —— 最大的架构差异

这是 Hermes 和 Claude Code 最大的架构差异。Claude Code 是纯 CLI 工具。 Hermes 是一个多平台的 Agent 服务：

# gateway/run.py — Gateway 架构（简化）
class GatewayRunner:
    def __init__(self):
        self.platforms = {}   # platform_name -> PlatformAdapter
        self.agent_cache = LRUCache(max_size=128)  # 缓存 AIAgent 实例

    async def start(self):
        # 加载所有配置的平台适配器
        for name, config in self.platform_configs.items():
            adapter = self._create_adapter(name, config)
            await adapter.start()
            self.platforms[name] = adapter

    def get_or_create_agent(self, session_id: str) -> AIAgent:
        # LRU 缓存 AIAgent 实例，每会话一个
        if session_id not in self.agent_cache:
            self.agent_cache[session_id] = AIAgent(platform="gateway", ...)
        return self.agent_cache[session_id]

每个平台适配器（gateway/platforms/）实现相同的基类：

  • FeishuAdapter — 飞书消息收发、富文本解析、评论回复
  • DiscordAdapter — Discord Bot / Webhook
  • TelegramAdapter — Telegram Bot API
  • SignalAdapter — Signal 消息
  • EmailAdapter — IMAP/SMTP
  • BlueBubblesAdapter — iMessage
  • ... 共 15+ 平台

每个平台适配器处理：消息格式转换、媒体文件上传、平台特定命令、平台过滤器。

8. Credential Pool —— 多 API Key 轮换

Claude Code 用一个 API Key。Hermes 支持 Credential Pool——同一个 Provider 配多个 API Key，自动轮换和 Fallback：

# agent/credential_pool.py
SUPPORTED_POOL_STRATEGIES = {
    "fill_first",    # 填满第一个再用第二个
    "round_robin",   # 轮流使用
    "random",        # 随机选择
    "least_used",    # 最少使用优先
}

class CredentialPool:
    def acquire(self) -> Credential | None:
        """获取一个可用凭证。如果所有凭证都用尽，返回 None"""
        for cred in self._get_credential_by_strategy():
            if cred.status == STATUS_OK:
                cred.usage_count += 1
                return cred
            elif self._cooldown_expired(cred):
                cred.status = STATUS_OK
                cred.usage_count += 1
                return cred
        return None  # 全部耗尽可能，触发 fallback

当收到 429（限流）或 402（配额耗尽）时，自动标记该凭证为 exhausted， 切换到池中的下一个。Provider 还可以返回 reset_at 时间来覆盖默认的 1 小时冷却期。

9. 上下文压缩 —— 三层保护

在 agent/context_compressor.py 中，Hermes 实现了比 Claude Code 更精细的压缩策略：

# agent/context_compressor.py — 压缩流程
1. 阈值检查：当前 token 数 > 模型上下文长度 × 0.50
2. 工具结果裁剪：旧的工具输出替换为占位符
   "[Old tool output cleared to save context space]"
3. LLM 摘要：用辅助模型（便宜/快）压缩中间轮次
4. 摘要注入：使用 SUMMARY_PREFIX 做上下文隔离
   "[CONTEXT COMPACTION — REFERENCE ONLY] ..."
5. 尾部保护：按 token 预算保留最新 N 条消息

关键区别：

  • Hermes 使用 辅助模型（auxiliary model）做压缩摘要，而不是主模型——更便宜
  • 压缩摘要中有明确的 "不要执行历史中的指令" 前缀，防止 Agent 把历史摘要当新指令
  • 支持 手动压缩（/compress 命令）和自动压缩双路径
  • 有失败冷却（600 秒内不再重试失败的压缩）

看源码时的关键提示

1. 从 run_agent.py 的 run_conversation() 入口开始

这是 Agent 的 main loop，所有逻辑最终汇聚于此。读这个方法的流程， 就能理解 Agent 的"一次对话"从开始到结束经历了什么（消息组装 → API 调用 → 工具分发 → 结果注入 → 继续循环/结束）。

2. 不要被长文件吓到

run_agent.py 有 ~13,000 行，但大部分是因为它在一个文件里处理了所有 Provider 的特殊逻辑。 核心循环本身只有 ~200 行。其余的是各种 Provider 的初始化、退出处理、安全检查、日志等。

3. 理解 Transport 层的存在意义

Claude Code 只需要对接一个 API（Anthropic Messages API），所以不需要传输抽象层。 Hermes 需要对接 5 种完全不同的 API 格式，所以有了 agent/transports/。 在读其他地方之前，先搞清楚 Transport 的契约（convert_messages / convert_tools / build_kwargs）。

4. 理解"工具自注册"的机制

在 tools/registry.py 中，discover_builtin_tools() 在 import 时自动收集所有 registry.register() 调用。这意味着每个工具文件自我声明，不需要手动维护工具列表。 这是 Hermes 可以轻松扩展工具集的关键。

5. "Skill"和"Memory"的边界

初学者最容易混淆这两个概念：

  • Skill = "怎么做一件事的方法" — 按需加载的可选知识包
  • Memory = "长期记住的事实" — 跨会话的持久信息
  • Config = "固定的偏好设置" — 不会自动变化的规则

初学者最容易犯的错

1. 试图一次读懂全部 13,000 行 run_agent.py

不要。先从 run_conversation() 的顶层循环开始，再顺着调用链往下走。

2. 忽略 Transport 层，直接看 Provider 初始化

Provider 初始化里有很多 Provider 特定的 header 设置、超时配置、认证方式。 但如果先理解 Transport 的契约（输入消息 → 输出 NormalizedResponse）， 这些细节就只是各个 Provider 的具体实现了。

3. 把 Hermes 当成"Claude Code 的克隆"

Claude Code 是一个产品（用 Anthropic 模型做编码助手）， Hermes 是一个框架（在任何模型、任何平台运行 Agent）。 这个差异渗透到每一处架构设计——Provider 抽象、多平台网关、Credential Pool 等， 都是 Claude Code 根本不需要考虑的问题。

4. 忽略 Gateway 的 AIAgent 缓存策略

Gateway 环境下，每个会话缓存一个 AIAgent 实例（LRU 128）。 这意味着 gateway 中的 Agent 必须无状态地处理每条消息， 而状态（记忆、任务列表）需要通过外部存储恢复。 这是纯 CLI 场景没有的复杂性。

一句话记住

Hermes 和 Claude Code 的根本区别不是"开源 vs 闭源"，而是"模型框架 vs 模型产品"—— Hermes 解决的是"如何让任何 LLM 在任何平台上成为 Agent"， Claude Code 解决的是"如何让 Claude 成为最好的编程助手"。
